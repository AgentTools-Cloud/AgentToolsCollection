Claim and edit your listing

Verify control of your service URL or host to edit its listings. Claiming is optional and free.

How it works

  1. Sign in at /account.
  2. Enter the full service URL, or the host you control.
  3. Publish the issued verification token using a method below.
  4. Click verify, then open the listing's edit link.

Claim a service URL

Use the full public HTTPS URL, including its path and query. This claim covers only that exact URL. Other paths, trailing-slash variants and queries are separate.

MethodPublish the proof
Public JSONAdd top-level agentToolsVerify to the claimed URL's JSON.
MCPExpose the public resource agent-tools://ownership with the JSON below. Verification reads this resource, not business tools.
GitHubCommit .well-known/agent-tools.json to the repository's default branch.
npmAdd agentToolsVerify to the latest package manifest.
 
{"agentToolsVerify":"<TOKEN>"}

Use public HTTPS on port 443. Private credentials, private addresses and redirects cannot supply proof.

Shared platforms require a service URL claim; they cannot be claimed as a whole host.

Claim a whole host

Use this only when you control the entire host. Verification covers its listings across x402, MCP and A2A.

MethodPublish the proof
Descriptorx402: add agentToolsVerify to /.well-known/x402. A2A: add it to /.well-known/agent-card.json or /.well-known/agent.json.
FileServe the token at /.well-known/agent-tools-verify.txt. Recommended for MCP servers, which do not need an x402 or A2A descriptor.
DNS TXTSet _agent-tools.<HOST> to atc-verify=<TOKEN>.

What you can edit

Listing typeEditable fields
x402name, description, category, tags, url, mcp_url
MCPname, description, tags, homepage_url, endpoint_url, cost_hint, auth_method, pricing
A2Aname, description, homepage_url, documentation_url, provider_name, card_url, endpoint_url

Measured values cannot be edited. Changing the primary endpoint requires verified destination control and clears its previous measurements.

x402 interface declarations and host-wide operations require a whole-host claim. Edits are recorded in public history and preserved during re-crawls.

Leave the token in place

After you publish the token, we also check automatically: for 24 hours for a service URL and 72 hours for a whole host, so you do not need to return. Lost the token? Request a new one.

Pending service URL tokens expire after 24 hours. Keep verified proof published: three consecutive failed re-checks revoke the claim. To reclaim a revoked URL, request and publish a new token.

Hosted MCP gateways

Some hosted gateways (currently server.smithery.ai) reject anonymous requests. Agent Tools reaches them with its own gateway key for verification and re-checks, so you do not need to send one: publish the agent-tools://ownership resource on your server and verify as usual.

Use the REST API

Send Authorization: Bearer <API_KEY>. Obtain a key with POST /api/v1/keys.

POST /api/v1/listing-claims
{"url":"https://provider.example/team/service/mcp"}

POST /api/v1/listing-claims/<CLAIM_ID>/verify
{"token":"<TOKEN>"}

GET /api/v1/listings/<KIND>/<SLUG>
PATCH /api/v1/listings/<KIND>/<SLUG>
{"description":"Updated description"}

For a whole host, use POST /api/v1/claims and its verify endpoint. Methods: /api/v1/claim-methods. Schemas: OpenAPI.

Use HTTP MCP

Connect to /mcp-discovery/ with the same Bearer header. API keys are not tool arguments.

claim_service_url(url, method=None)
publish the returned token
verify_service_url(claim_id, token)
get_owned_listing(kind, slug)
edit_owned_listing(kind, slug, fields)

Old Smithery proxies are retired. Use the current vendor URL; historical associations require separate review.

Never put private credentials in a URL or proof document. Privacy · Contact support.
